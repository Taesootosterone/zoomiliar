# Zoomiliar · 마루

최대 10명이 목소리와 화면으로 모이는 작은 웹 통화 앱입니다. 카메라, 녹화, 채팅, 가입, 회의 시간 제한은 없습니다. 입장 시 음소거되며 화면은 한 번에 한 명이 공유합니다. **현재 자체 호스팅용 MVP이며 공개 서비스로 배포하지 않았습니다.**

## 내 Mac에서 먼저 켜보기

1. [Node.js](https://nodejs.org/)에서 LTS 버전(22 이상)을 설치합니다.
2. 이 저장소의 **Code → Download ZIP**을 눌러 내려받고 압축을 풉니다.
3. Mac의 **터미널** 앱을 엽니다. `cd `를 입력하고(끝에 공백 포함), 압축을 푼 폴더를 터미널로 끌어 놓은 다음 Enter를 누릅니다.
4. 아래 명령을 한 줄씩 실행합니다.

   ```sh
   npm ci
   npm start
   ```

5. 데스크톱 Chrome에서 **http://localhost:3000**을 엽니다. 이름을 입력하고 방을 만듭니다. 마이크 권한을 허용합니다.
6. **초대 링크 복사**를 눌러 같은 컴퓨터의 다른 브라우저 창에 붙여 넣으면 먼저 확인할 수 있습니다. 실제 대화에서는 이어폰을 사용하세요.
7. **마이크 켜기 / 음소거**, **화면 공유 / 공유 중지**, **나가기**만 사용하면 됩니다. 공유 선택 창에서 보여줄 창이나 탭을 선택하세요. Mac이 화면 기록 권한을 요구하면 시스템 설정에서 브라우저에 허용합니다. 여기서 운영체제가 부르는 ‘화면 기록 권한’은 화면 캡처 권한이며 이 앱은 파일을 녹화하지 않습니다.
8. 서버를 끄려면 터미널에서 **Control+C**를 누릅니다. 터미널 종료, 컴퓨터 잠자기, 서버 재시작 시 통화가 끊길 수 있습니다.

**localhost 링크는 다른 사람의 컴퓨터에서는 사용할 수 없습니다.** 아래 인터넷 연결 준비가 끝나야 친구에게 실제로 공유할 수 있습니다. 모바일 화면 공유는 지원 대상으로 삼지 않았습니다. 시스템/탭 소리는 공유하지 않으며 마이크 음성만 전달합니다.

## 인터넷에서 함께 쓰려면 (운영자 설정)

추가 서비스 가입이나 배포는 자동 수행하지 않습니다. 이미 보유한 서버 또는 항상 켜둘 컴퓨터를 사용할 수 있습니다.

1. Node 서버를 구동할 장비와 외부에서 접속 가능한 주소를 준비합니다. 방화벽/공유기 설정과 DNS는 운영 환경에 맞게 적용해야 합니다.
2. Caddy 또는 Nginx 같은 역방향 프록시에서 **유효한 HTTPS 인증서**를 사용하고 WebSocket 업그레이드를 지원하도록 `127.0.0.1:3000`으로 연결합니다. HTTP로 LAN IP만 공유하면 브라우저가 마이크/화면 권한을 차단합니다. 공개 인터넷으로 Node 포트를 직접 노출하지 마세요.
3. `.env.example`을 `.env`로 복사하고 `PUBLIC_ORIGIN=https://실제주소`를 설정합니다. 끝에 `/`는 넣지 않습니다. HTTPS는 프록시가 처리합니다. 기본 바인딩은 localhost입니다. 컨테이너/별도 프록시라면 필요한 경우 `HOST=0.0.0.0`과 방화벽을 함께 설정합니다.
4. STUN/TURN 서버를 준비하고 `.env`의 `ICE_SERVERS_JSON` 배열에 설정합니다. 기본은 `[]`이며 공용 STUN 서비스에 자동 연결하지 않습니다. 서로 다른 회사망/모바일망/엄격한 NAT에서는 STUN만으로 연결되지 않을 수 있어 TURN이 필요합니다. TURN은 실제 미디어를 중계하므로 대역폭 비용이 생길 수 있습니다.
5. `npm start`로 실행한 다음 **서로 다른 인터넷 회선**의 두 기기로 먼저 테스트합니다. HTTPS 주소에서 생성한 링크를 신뢰하는 사람에게만 전달합니다.
6. 10인 사용 전 2인 → 5인 → 10인 순으로 음성/화면/재입장 검증을 진행합니다. 3시간 이상 실제 통화, 화면 공유 반복, 회선 변경, Mac 잠자기 및 네트워크 복구를 확인하세요.

Caddy를 이미 설치하고 실제 도메인/DNS/80·443 포트를 준비한 운영자를 위한 예시:

```caddyfile
call.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

프록시 WebSocket 제한 시간, 호스트의 자동 종료/유휴 절전, TURN allocation/자격 증명 수명을 장시간 통화 요구에 맞춰야 합니다. 이 MVP는 연결 실패 시 안내하고 나갔다 재입장하도록 합니다. 자동 재연결/ICE 재시작은 구현하지 않았습니다.

## 비용과 성능: 어디까지 무료인가요?

앱 자체의 분당 과금이나 통화 종료 타이머는 없습니다. 보유 장비와 인터넷으로 직접 연결된다면 통화 서비스 이용료 없이 사용할 수 있습니다. **호스팅·도메인·전기·인터넷 데이터·TURN 트래픽까지 모두 무료라는 뜻은 아닙니다.** 무료 호스팅의 절전/사용량 제한이 장시간 통화를 끊을 수도 있습니다.

WebRTC mesh 방식이므로 10명은 총 45개의 참가자 간 연결을 만듭니다. 한 사람이 화면을 공유하면 그 화면을 다른 9명에게 각각 보냅니다. 예를 들어 화면 스트림이 상대당 1 Mbps라면 발표자 업로드만 약 9 Mbps(약 4 GB/시간, 프로토콜 오버헤드 제외)가 필요합니다. 실제 비트레이트는 브라우저/화면 내용/회선에 따라 다릅니다. 캡처는 720p·10fps를 우선 요청하고 최대 1080p·15fps로 제한합니다. 10명 안정성을 보장하지 않으며, 잦은 10인 사용에는 SFU 미디어 서버를 사용하는 후속 버전이 적합합니다.

## 개인정보와 접근 제어

- 방 링크는 암호학적으로 무작위인 128비트 토큰입니다. 토큰은 URL fragment(`#...`)에 있고 입장 시 WebSocket으로 서버에 전달됩니다. **링크를 가진 누구나** 방에 들어올 수 있습니다. 비밀번호·호스트 승인·강퇴·계정 인증은 없습니다.
- 서버는 방/참가자 이름/음소거 상태를 메모리에만 유지하고 비어 있는 방을 지웁니다. 앱은 미디어 녹화, DB, 분석 추적, 외부 폰트/스크립트를 사용하지 않습니다. 같은 링크는 나중에 새 방으로 재사용될 수 있으며 만료/폐기 기능은 없습니다.
- WebRTC 미디어는 전송 중 암호화됩니다. 서버는 연결 신호(IP 후보/SDP 등)를 처리하고, 직접 연결 시 참가자끼리 IP 주소가 노출될 수 있습니다. STUN/TURN 운영자도 네트워크 메타데이터를 볼 수 있습니다. HTTPS 호스트와 제공되는 코드를 신뢰해야 하므로 인증된 종단간 보안 제품으로 간주하지 마세요.
- `/config`의 ICE 설정은 브라우저에 공개됩니다. **TURN 관리자 비밀번호나 장기 공유 비밀키를 넣지 마세요.** 제한된 수명/할당량을 가진 전용 클라이언트 자격 증명만 사용하세요. 공개 서비스 규모에는 인증된 임시 TURN 자격 증명 발급 API가 추가로 필요합니다.
- 같은 방 내부로만 신호를 전달하고, Origin 검사, 최대 메시지 크기, 초당 메시지 제한, WebSocket heartbeat 및 10인 제한을 적용했습니다. 인터넷 전체에 무인 공개할 정도의 인증/남용 방지/운영 모니터링은 없습니다. 프록시 로그나 참가자 자체 녹화까지 막을 수는 없습니다.

## 개발과 테스트

```sh
npm ci
npm test
# Chromium이 설치된 Linux 환경
npm run test:browser
# 다른 설치 위치는 CHROMIUM_PATH=/path/to/chromium 지정
```

`test/server.test.js`: 10명 입장/11번째 거절/자리 재사용/방 정리, 방 간 신호 격리, 음소거 상태, 화면 공유 잠금 및 퇴장 정리, 잘못된 메시지/방 코드/Origin 거절, 비공개 파일 차단.

`test/browser.js`: Chromium 3개 탭의 실제 WebRTC 연결과 음성 수신 RTP, 화면 수신/디코딩, 음소거, 공유 중지/재시작, 공유 중 늦은 입장, 퇴장 정리, 마이크 거절, 데스크톱/모바일 스크린샷. 마이크는 Chromium 테스트 장치이고 화면 선택기만 canvas 스트림으로 대체합니다. 따라서 실제 운영체제 화면 선택 권한, 서로 다른 NAT, TURN 경유, 10명 미디어 부하, 여러 시간 지속성까지 검증하는 테스트는 아닙니다.

공식 참고: [WebRTC TURN 안내](https://webrtc.org/getting-started/turn-server), [MDN 화면 캡처 권한/HTTPS 요구사항](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia).

### 이 작업 환경에서의 검증 한계

관리형 Chromium의 `WebRtcIPHandling=disable_non_proxied_udp` 정책으로 직접 ICE 후보가 생성되지 않아 실제 미디어 전송 테스트는 차단되었습니다. 정책은 변경하지 않았습니다. `SKIP_MEDIA_TESTS=1 npm run test:browser`는 미디어 전송 검증을 명시적으로 건너뛰고 연결 협상 및 UI 흐름만 검사합니다. 이 모드 통과는 음성/화면 전송 성공을 의미하지 않습니다. 제한 없는 테스트 기기에서 기본 `npm run test:browser`와 실제 사람 간 통화를 반드시 확인해야 합니다.
